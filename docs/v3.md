# v3 — terminal portfolio

One static HTML page: a CRT-terminal simulation with a virtual filesystem
(`ls`, `cat`, `cd`) exposing the same content a normal portfolio would
put in sections — about, experience, education, skills, achievements,
projects, contact, resume. `help` lists every command.

## Layout

```
index.html          the site (HTML/CSS/JS, self-contained)
llms.txt            plain-text mirror for AI agents/bots
favicon.svg          site icon
docs/screenshot.png  README screenshot (not deployed)
```

The deployed site is just `index.html`, `llms.txt`, and `favicon.svg` -
no build step, no framework, no data file to keep in sync. Content
lives directly in `index.html`, so a content change is an edit to that
file.

## Local preview

Open `index.html` directly in a browser, or:

```bash
python3 -m http.server
```

## Deploy

`.github/workflows/deploy.yml` copies the three files above into a
GitHub Pages deployment on every push to `main`. No install, no build.

## Why not a framework

v2 was Next.js. v3 trades that for one static file: no build tooling
between "type a command" and "see it happen," instant load, nothing to
keep patched.
