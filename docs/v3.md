# v3 — terminal portfolio

One static HTML page: a CRT-terminal simulation with a virtual filesystem
(`ls`, `cat`, `cd`) exposing the same content a normal portfolio would
put in sections — about, experience, education, skills, achievements,
projects, contact, resume. `help` lists every command.

## Layout

- `templates/index.template.html` — the actual site. Tested, self-contained
  HTML/CSS/JS, no framework, no build step required to view it.
- `info.json` — the handful of fields that change on their own schedule
  (resume link, contact email, meta description). Edit this, push to
  `main`, and `scripts/build.mjs` bakes the new values into the deployed
  page. Everything else (bio, experience, projects, quotes, ...) lives
  directly in the template; change it there.
- `scripts/build.mjs` — reads `info.json` + the template, writes `dist/`
  (`index.html`, `404.html`, `resume/index.html`, `llms.txt`, favicon).
  `dist/` is what GitHub Pages serves; it isn't committed, it's rebuilt
  by CI on every push (see `.github/workflows/deploy.yml`).

## Local preview

```bash
node scripts/build.mjs
npx serve dist    # or: python3 -m http.server -d dist
```

## Why not a framework

v2 was Next.js. v3 trades that for a single static file: no build tooling
between "type a command" and "see it happen," near-instant load, nothing
to keep patched. The trade-off is that layout content lives in the
template's markup rather than in structured JSON — acceptable here since
the content is small and changes rarely.
